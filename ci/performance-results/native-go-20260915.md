# Native Go optimization evidence — 2026-09-15 UTC

The PR retains three Go changes with modest, workload-specific measured gains: avoid building painted SVG during Markdown dimension measurement; reuse per-operation text measurement state and measure legend labels once; and use typed node sorting. None establishes that every diagram becomes faster. The routing scratch-map candidate was rejected because its predeclared screen did not establish a runtime improvement.

The direct original-baseline comparison reduced pipeline time by 0.254% across all 246 successful cases and by 0.913% across the ten public diagrams. The 24 Markdown cases showed a larger pipeline reduction of 1.750%. These are workload-specific aggregate estimates; the full intervals and unfavorable observations follow.

The [compact evidence ZIP](native-go-20260915.zip) contains original numeric rows, exact frozen runners and estimator, full per-case results and confidence intervals, reproduction instructions, and the rejected experiment. Private source diagrams, descriptive identifiers, private paths, font bytes, errors and SVGs are excluded. Private cases use stable opaque IDs.

## Retained changes and incremental results

1. **Markdown dimensions only** (`d6a52f13359dc957e346c792507728c6fd3b0c76`): preserve layout and validation while avoiding the painting path when only dimensions are needed. Its fixed 24-case Markdown confirmation reduced pipeline time by 0.783%.
2. **Ruler and legend measurement reuse** (`bb3efe8217e676663a502f9d49b9598e310b10d2`): let the native SVG CLI reuse its compiler ruler, share lazy measurement state within a render operation, and measure legend rows once. The fixed 25-case target confirmation reduced pipeline time by 0.935%; full-corpus pipeline time was inconclusive.
3. **Typed node sorting** (`cccf1c79f309f4220e5bd49dcfdcffea61857a9e`): replace reflection through `sort.Slice` with `slices.SortFunc` and `cmp.Compare`. The Go 1.27 implementation retains the same sorting algorithm, comparator order and guards. Full-corpus pipeline time fell 0.396%, with fewer allocated bytes and objects.

## Correctness and measurement boundaries

The initial corpus contained ten public real-world diagrams and 237 private records. Each full correctness preflight produced 246 byte-identical successful SVG pairs and one matching existing error. All retained benchmark sample SVGs matched their oracle. Step 4 also passed full-corpus correctness before its smaller performance screen. Local correctness evidence includes renderer/CLI/E2E and focused race checks, 84 exact pointer-sequence sort differential cases, TALA tests, and routing lifecycle/accounting/cancellation tests. Correctness alone did not qualify an optimization for acceptance.

A clean rebuild of final accepted source reproduced the frozen Step 3 runner SHA-256, `a7d907dbf13113349fb6d957603da5e4b153baf18d8d5f44365290d5ff6938dc`. Separate native CLI checks matched all ten public outputs. An actual public reproduction-controller smoke also passed ten exact preflight pairs and 100 sample rows (two timing pairs, zero warmups and three allocation pairs per case), including real identities, AB/BA ordering and phase completion. These 100 rows are validation only and are excluded from campaign totals and performance claims. Applicable hosted checks for the measured accepted source passed; skipped nonapplicable checks are recorded separately. These local and hosted correctness claims are distinct from numeric recalculation.

Runs use Go 1.27.0 on an Apple M4 with 10 CPUs and 16 GiB RAM, running macOS 26.6.2/arm64, CGO disabled, one fresh process at a time, unchanged seeded TALA work and native inner parallelism. Baseline/candidate invocations are adjacent pairs with alternating AB/BA order; cases are shuffled each round. Wall time includes startup, input/output and teardown. CPU sums user and system time across threads; RSS is peak process memory, not allocated bytes. Pipeline timers include font/ruler setup through rendering. Allocation counters are measured separately, without forced GC. This is an active desktop without CPU affinity or OS isolation, and is not a warm-service benchmark.

Intervals use 2,000 paired percentile bootstrap replicates, with whole round blocks shared across cases. The corpus itself is not resampled: intervals describe these observed workloads, not unseen diagrams. Individual intervals are unadjusted for multiple comparisons. The frozen estimator also retains equal-case geometric estimates in the ZIP. Do not add incremental percentages or multiply their intervals to infer a cumulative result.

The bundle retains 33,640 original numeric rows across eleven campaigns, including the rejected screen, direct cumulative comparison and its separate confirmation. Step 1 contributes 8,680 rows; Step 2, 8,930; Step 3, 7,880; the rejected Step 4 screen, 420; and the direct full run plus confirmation, 7,730. Recalculating distributed rows verifies numeric values, pairing, completeness and every published statistic. It cannot independently establish omitted private input/config/SVG identities. Authentic original-file digests identify retained local evidence; no fabricated hashes stand in for redacted fields.

The ZIP contains exact v1/v2 runners and the frozen analysis script. Step 1 used v1. Later comparisons use v2, which reflectively adopts the optional ruler field to support identical benchmark source against both old and new APIs; this adapter cost is inside measured rendering/pipeline/allocation work. Production CLI code uses direct assignment. The expanded ZIP, including duplicate runner main packages and the rejected Go test, must be extracted outside a Go module. Only this report and the ZIP belong under `ci/performance-results/` in the repository.
